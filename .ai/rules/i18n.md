# Internationalisation

One locale ships today (`en`). The rules exist so the catalog does not decay before a second
one arrives — a hardcoded sentence costs nothing until the day it costs everything.

## Every user-facing string lives in `messages/en.json`

Read it with `useTranslations` in client components and `getTranslations` in Server
Components. Top-level namespaces:

`app`, `common`, `footer`, `landing`, `notFound`, `dashboard`, `containers`, `states`,
`spinUp`, `destroy`, `actions`, `validation`, `errors`, `signIn`, `presets`.

`global.d.ts` declares next-intl's `AppConfig["Messages"]` against the catalog, so **keys are
type-checked**: a renamed or misspelled key fails `pnpm typecheck`, not at runtime.

## A hardcoded sentence is a build failure

`i18next/no-literal-string` runs on `src/**/*.tsx` in `mode: "jsx-only"`. The message it
prints is the whole instruction: _"Move this string into messages/en.json and read it with
`t()`."_

The rule is configured with allowlists, and knowing what is on them stops you from
misreading a real violation as a false positive:

- **Callees excluded** — `t`, `t.rich`, `tCommon`, `useTranslations`, `getTranslations`,
  `cn`/`cva`/`clsx`/`twMerge`, and the local `fieldError` helper. A catalog key is not copy;
  without these the rule would report `t("submit")` and argue with its own fix.
- **JSX attributes excluded** — styling and identifiers (`className`, `href`, `src`, `id`,
  `key`, `name`, `value`, `data-*`, `aria-hidden`) and component APIs whose values are enum
  members rather than sentences (`type`, `role`, `variant`, `size`, `tone`, `shape`, `side`,
  `align`, `orientation`, `position`, `swipeDirection`, `autoComplete`, `labelKey`).
- **Object properties excluded** — `role`, `aria-live`, `aria-*`, `*className`, `tone`.
  Props forwarded as an object (ScrollArea's `viewportProps`) carry protocol, not prose.

**Do not widen an allowlist to silence a violation.** If the rule fires on real copy, the
copy belongs in the catalog. The allowlists describe what is structurally not copy; adding
to them is a change to that claim and needs the same justification as any other rule edit.

Test files (`src/**/*.test.tsx`) and `src/test/**` are exempt, because a test asserting real
copy has to write it out.

## Code that cannot translate itself returns a descriptor

Error classes and the log monitor run far from any request scope, and next-intl's translator
is async. They return a `MessageDescriptor` — `{ key, values? }` — and let the rendering
layer resolve it. See `src/lib/messages.ts`.

New error copy is therefore **two** edits, and both are required:

1. A new member of the `MessageKey` union in `src/lib/messages.ts`.
2. The matching entry under `errors.*` in `messages/en.json`.

The union is hand-maintained on purpose: it is the list of keys reachable from non-rendering
code, and keeping it narrow is what stops a raw upstream sentence being thrown as copy. See
[errors-and-logging.md](errors-and-logging.md).

## ICU arguments are checked by the tests, not by the linter

`src/test/setup-intl.ts` builds a real `createTranslator` over `messages/en.json`, so a unit
or Server Action test fails if the key is missing, if an ICU argument is misnamed, or if a
plural form is malformed. Assert against real rendered copy, not against key echoes — that
is the whole reason the real translator is wired up instead of a stub. See
[testing.md](testing.md).

## Before you call this done

`pnpm lint` catches hardcoded JSX and `pnpm typecheck` catches unknown keys, so `pnpm check`
covers both. To find keys you added to the catalog but never used:

```sh
node -e 'const m=require("./messages/en.json");const walk=(o,p="")=>Object.entries(o).flatMap(([k,v])=>typeof v==="object"?walk(v,`${p}${k}.`):[`${p}${k}`]);console.log(walk(m).join("\n"))' \
  | while read -r k; do grep -rqF "${k##*.}" src || echo "unused? $k"; done
```

That is a heuristic — nested namespaces are read as `t("child")` under a namespace, so it
reports the leaf. Treat hits as candidates to check by hand, not as a list to delete.
